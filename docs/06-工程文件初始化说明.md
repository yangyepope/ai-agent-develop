# 06 · 工程文件初始化说明

## 先说结论

不需要“每个文件都手工逐个创建”。

一般来说，工程初始化通常是下面这套流程：

1. 先创建项目骨架
2. 再生成通用配置文件
3. 最后根据需要补充本地私密文件

也就是说：

- `package.json`、`tsconfig.json`、`eslint.config.mjs` 这类文件，通常是初始化工程时自动生成，或者根据模板补齐
- `.env` 这类文件，通常是本地启动前手动创建
- `.env.example` 是给别人复制用的模板文件，通常会提交到仓库里

---

## 这些文件一般怎么来？

### 1) `package.json`

这是项目的“说明书”和“命令入口”。

通常由下面方式生成：

```bash
npm init
```

或者直接用脚手架：

```bash
npm create vite@latest my-app
```

它里面通常保存：

- 项目名称
- 依赖列表
- 脚本命令，例如 `npm run dev`、`npm run test`
- 版本信息

### 2) `tsconfig.json`

TypeScript 的配置文件，通常由下面命令生成：

```bash
npx tsc --init
```

然后根据项目需求再修改配置项，比如：

- `strict: true`
- `module: "nodenext"`
- `noEmit: true`
- `erasableSyntaxOnly: true`

### 3) `eslint.config.mjs`

这是 ESLint 的配置文件，用来做代码质量检查。

通常在安装 ESLint 后手动生成或配置：

```bash
npm install -D eslint
```

然后根据项目需求写规则，例如：

- 禁止未使用变量
- 禁止忘记 `await`
- 禁止不安全的异步写法

### 4) `.prettierrc.json`

这是 Prettier 的格式化配置文件，用来统一代码风格。

比如：

- 单引号还是双引号
- 缩进是 2 空格还是 4 空格
- 是否保留尾随逗号

它的作用是“格式化”，而不是“逻辑检查”。

### 5) `.env.example`

这个通常是模板文件，给别人复制用。

例如：

```bash
cp .env.example .env
```

里面放的是变量名和示例值，方便团队共同维护。

### 6) `.env`

这个是真实的本地环境变量文件。

一般是手动创建的，里面放：

- API Key
- 服务地址
- 本地调试参数

它通常不会提交到 Git，因为它是本地机密信息。

---

## 什么时候需要手动创建？

通常是下面几种情况：

### 需要手动创建的

- `.env`：本地真实配置文件
- `.env.example`：模板文件
- 一些项目特定的配置文件

### 通常自动生成的

- `package.json`
- `tsconfig.json`
- `eslint.config.mjs`
- `.prettierrc.json`

---

## 这个项目里为什么看起来像“很多文件都在一开始就存在”？

因为这里的工程已经初始化完成了，文件结构已经搭好。

你看到的这些文件，不一定是某个人手工逐个写出来的，而是：

- 工程模板已经生成
- 配置项已经按项目要求定好
- 目录和代码结构已组织完成

这和“从零开始手工搭工程”是两回事。

---

## 一个最直观的理解

可以把这些文件想成：

| 文件                  | 作用                    | 什么时候创建         |
| --------------------- | ----------------------- | -------------------- |
| `package.json`        | 项目依赖 + 命令入口     | 初始化项目时         |
| `.nvmrc`              | 指定 Node 版本          | 通常手动补充         |
| `tsconfig.json`       | TypeScript 类型检查配置 | 生成或手配           |
| `tsconfig.build.json` | 构建产出时使用          | 需要构建时才配       |
| `eslint.config.mjs`   | 代码质量规则            | 初始化/安装后补上    |
| `.prettierrc.json`    | 代码格式规则            | 安装 Prettier 后补上 |
| `.env`                | 本地真实密钥            | 启动前手动创建       |
| `.env.example`        | 变量模板                | 提交到仓库           |

---

## 一句话总结

> 不是每个文件都需要手工新建，很多都是“初始化工程时自动生成”，而 `.env` 这类本地敏感配置才是通常需要手动创建的。

在学习项目里，理解这些文件的职责，比背诵“谁手工创建”更重要。
